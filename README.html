User Login Automation

A beginner-friendly UI automation framework using Java 21, Playwright for Java, Maven, TestNG, Page Object Model, JSON test data, ExtentReports, and optional Jira Cloud reporting.

What each file does

Build and configuration

pom.xml

Declares Java 21 and the Playwright, TestNG, Jackson, and ExtentReports dependencies. Maven Surefire discovers and runs the TestNG tests.

Jenkinsfile

Defines the CI pipeline: checkout, Chromium installation, headless test execution, Jira credential binding, and report/artifact publishing.

config.properties

Stores the application URL, browser type, and headless setting. Page locators are kept in the page object, not this file.

ConfigReader.java

Loads config.properties and provides the application URL and browser settings to other classes.

PlaywrightFactory.java

Selects and launches the configured browser, then creates the browser context and page. Closes these resources after the test.

BaseTest.java

Starts a new browser and page before each TestNG method and closes them afterward. Makes the active page available to the failure listener.

LoginPage.java

Implements the login Page Object. It owns page locators and actions to open the form, enter credentials, submit, and read the outcome.

Test data and tests

UserLoginPOJO.java

A Java object containing username, password, and expectedResult fields, with constructors, getters, and setters.

login-data.json

Contains one JSON object per scenario. Use only test credentials authorized for your test environment; never store real or production credentials here.

JSONDataReader.java

Uses Jackson to deserialize the JSON array into UserLoginPOJO objects. Reports a missing, invalid, or empty data file.

UserLoginTest.java

Its DataProvider creates one TestNG data row per POJO. The test drives LoginPage and asserts that the displayed result matches expectedResult.

For example, this JSON object is converted into one UserLoginPOJO and passed to the test method:

{
  "username": "student",
  "password": "replace-me",
  "expectedResult": "Logged In Successfully"
}

Reporting and Jira

TestListener.java

Records passed, failed, and skipped tests in ExtentReports. On failure it captures a screenshot before browser cleanup, adds it to the report, and requests Jira reporting when configured.

JiraClient.java

Calls Jira Cloud REST API, searches for an existing issue with the same failure fingerprint, creates a Bug when needed, and can attach the failure screenshot.

jira.properties.example

Shows non-secret Jenkins settings: Jira base URL and project key. Store Jira email and API token in Jenkins credentials instead.

How a test run works

  1. Maven Surefire starts the TestNG tests.
  2. BaseTest starts a fresh browser and page before each test method.
  3. JSONDataReader loads scenario records; the DataProvider supplies one record to each test invocation.
  4. UserLoginTest uses LoginPage to submit the scenario and check the result.
  5. TestListener records the result in ExtentReports. On failure, it captures a screenshot before teardown closes the browser.
  6. When all four Jira environment variables are present, JiraClient searches for a duplicate failure, creates an issue if needed, and attaches the screenshot.
  7. TestNG teardown closes browser resources. The listener writes the HTML report under target/extent-reports/.

Configure the application

Edit src/main/resources/config.properties:

application.url=https://your-application.example/login
browser.type=chromium
browser.headless=true

Set the URL to your actual test application. In LoginPage.java, update the accessible locators and success-page detection to match that application's labels, button name, result element, and URL behavior. The expected messages in login-data.json must exactly match the application output.

Test data safety: Use authorized test accounts. Do not commit credentials or put production credentials in JSON.

Install browser and run tests

Run commands from the project directory. Install the browser selected by browser.type:

mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"
mvn clean test

For Firefox or WebKit, install the browser you configured instead:

mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install firefox"
mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install webkit"

The UI tests need a reachable application, matching selectors, valid test data, and expected messages that match its behavior.

Output files

  • target/surefire-reports/ — Maven and TestNG results and failure details.
  • target/screenshots/ — Screenshots captured for failed tests.
  • target/extent-reports/ExtentReport.html — ExtentReports HTML output with test statuses. Failure screenshots are copied into its screenshots/ subfolder.

Screenshot links are relative to the report directory. The Jenkins pipeline publishes all files in this directory using the HTML Publisher plugin; install that plugin on the Jenkins controller for the report link to appear.

Optional Jira Cloud failure reporting

The listener reads these environment variables at runtime:

  • JIRA_BASE_URL — Jira site URL, such as https://your-site.atlassian.net.
  • JIRA_EMAIL — Email address for the Jira account that creates issues.
  • JIRA_API_TOKEN — API token for that account.
  • JIRA_PROJECT_KEY — Project key where failure Bugs should be created.

The Jira account needs permission to create issues in the project and attach files. Example PowerShell setup for a local run:

$env:JIRA_BASE_URL = "https://your-site.atlassian.net"
$env:JIRA_EMAIL = "your-jira-email@example.com"
$env:JIRA_API_TOKEN = "your-api-token"
$env:JIRA_PROJECT_KEY = "PROJECT"
mvn clean test

Keep the API token out of source code and test data. If Jira isn't configured, the test still reports its failure and saves its screenshot, but no Jira issue is created. Partial Jira configuration is reported by the listener.

Jenkins CI/CD

The root-level Jenkinsfile is a declarative pipeline that supports Windows and Linux agents. Configure Jenkins with:

  1. Java 21 and Maven installed and available on the agent's PATH.
  2. The Jenkins Credentials Binding plugin.
  3. Two Secret text credentials with IDs jira-email and jira-api-token.
  4. Non-secret JIRA_BASE_URL and JIRA_PROJECT_KEY environment variables in the job or agent configuration.
  5. An agent that can access the application and has the operating-system libraries Chromium requires. The pipeline installs Chromium itself.
  6. A Pipeline or Multibranch Pipeline job configured to load this repository's root-level Jenkinsfile.

The pipeline runs tests headlessly using mvn clean test -Dbrowser.headless=true. This system property overrides the value in config.properties for CI without changing your local browser setting. It publishes TestNG results and archives test reports and screenshots even after a failure. Jira reporting uses the Jenkins credentials and the URL/project-key environment variables.
